# 像素音乐 MV

直接交付成片。若用户仅要分镜、提示词或一段预览，按这次指定的范围交付。使用用户提供的录音作为音乐母带，为新歌建立独立目录。缺少母带时先从本次附件、指定项目和可用的同名文件中寻找；确实取不到时，请用户提供音频。

## 听歌与对词

1. 显式选取歌曲的音轨；MP3 也可能内嵌封面视频流。用解码后的采样数和采样率确定实际播放时长。完整保留原曲，包括前后留白、段间呼吸及尾音。
2. 优先读取用户歌词和录音内嵌的歌词，把它们作为候选文本。对原曲运行支持演唱语言的 Whisper、faster-whisper 或同等对齐工具。自由识别用来确认实际顺序及重复，再用候选歌词做短语级强制对齐。用重叠窗口、波形或回听复核连唱、长音、间奏和尾奏。伴奏中容易出现幻觉，不把它贴进字幕。仅在错听确会改变歌词而录音及原词均无法定夺时，列出有疑问的那一句。
3. 给每个唱出的短语单独记录开始、结束和文本。人声休止时清空字幕。纯器乐曲使用空歌词时间轴，按音乐结构剪辑。歌词和分镜分开保存为 UTF-8 JSON，默认以秒为单位，开始含、结束不含。

## 画风与叙事

默认延续《冰箱里的大象》受认可的 16-bit 独立游戏过场质感。用清晰的方像素轮廓和有限色板，阴影偏暗紫或酒红，局部暖光，轻微抖色、CRT 扫描线和颗粒。人物常用呼吸、眨眼、手势等有限帧动画。低分辨率原画以最近邻放大，字幕使用有目标语言字形的点阵字体、米白字和深色阴影，居下并保留安全边距。根据新歌或用户指定的风格调整色调、比例与节奏。

从**本首歌**选主角、场景、反复出现的物件和一个有变化的结尾。先做角色与场景基准图，再以它保持不同镜位一致。前奏交代空间，主歌推动动作，副歌用重要词或呼吸点安排视觉变化，间奏和尾奏留给环境及细节。日常动作可以循环，歌曲中再次出现同一句时，可以换视角、姿态或改变同一物件的状态。全片须随段落发展。

用户要沿用以前作品的具体人物或镜头时，从用户提供的工程或素材中读取原画。仅借用画风时，为新歌另做角色、道具和故事。参考工程缺失时仍可依上述风格规格制作。沿用原有导出程序时，替换旧工程中与该曲绑定的歌词列表、音频窗口、音频采样数、分镜、时长与画面素材。

## 成片与校验

默认制作 1920×1080、16:9、24 fps、H.264 + AAC 的 MP4。将完整原曲一次转为交付音轨，两版复用同一音频。先制作无字幕画面，再叠加字幕生成有字幕版。用最后画面的展示时长吸收“歌曲时长 × 帧率”的余数。检查播放器的音视频轨开始和结束时间，区分 AAC 编码器延迟和实际播放长度。保留已有工程与成品，修订另存。

按需使用 `scripts/mv_timeline.py`。它支持 `measure AUDIO`，也支持 `check --lyrics lyrics.json --scenes scenes.json --duration SECONDS --srt OUTPUT.srt`。两份 JSON 分别使用 `cues` 和 `scenes` 列表，条目均有 `start` 和 `end`，歌词条目另有 `text`。分镜从零开始连续覆盖整首歌；字幕允许间隔。工具只校验已对齐的数据，演唱证据来自前面的音频分析。

仓库内的 `render.py` 可将用户音频、PNG 或动画 GIF 及两份时间轴渲染为成片。每个分镜增加 `asset` 字段，使用相对于分镜 JSON 的素材路径。中文歌词用 `--font` 指定含所需字形的本地字体。详细命令见仓库 README。

导出后实际解码两版，核对分辨率、标称帧率、音轨与精确播放时长。比对两版同一时刻的字幕区域，复查首句、重复句、间奏与最后一个字的出入点。适合时对比原曲和导出音轨在开头、中段及尾部的相关性或采样偏移。分别交付有字幕 MP4、无字幕 MP4、SRT、歌词 JSON、分镜 JSON，以及可编辑源工程（渲染代码、必要素材和重建说明）。按实际做过的检查报告结果。
